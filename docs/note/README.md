# note 入稿メモ（けいさんカード）

このフォルダの中身は、note の連載「教室で使えるかもしれないもの作り」に
そのまま出せる状態の記事一式です。

```
docs/note/
├── keisan-card-note-article.md   記事本文
├── images/                       実際に操作して撮った画面（19点）
└── README.md                     このファイル
```

## 貼るまえに直すところ

### 連載番号

記事の1行目が `#◯` のままです。**ここだけは手で直してください。**

推測で埋めていません。公開ずみの記事から番号を確かめることができなかったためです
（note がこの環境からの読み取りを拒否します）。前回の記事の番号 +1 に直してください。

### 前作へのリンク（任意）

「🏫 はじめに」には、いまのところ前作へのつなぎを入れていません。
連載のどれと地続きにするかは書き手が決めるところなので、空けてあります。
入れるなら、17行目の「そこで、計算カードをまるごと〜」の前に一段落、
「以前この連載で紹介した◯◯と同じで、記録はその端末の中だけに残ります」
のような形で足すと収まります。

### 教室での実践

意図的に「使ってみたら子どもたちが〜」を一切書いていません。
作者の実践記録ではないためです。書けたのは「こうなればいいと思って作った」までです。
実際に使われたあとの様子は、書き手が自分の言葉で足すところとして空けてあります。
足すなら「📝 まとめ」の最後から2段落目あたりが自然です。

## note に貼る手順

1. note の新規記事を開き、タイトル欄に記事の1行目（`# ` を除いた部分）を貼ります。
2. 本文は、2行目から最後までをそのまま貼ります。note のエディタは
   見出し記号 `##` をそのまま見出しに変換します。目次は自動で作られます。
3. 画像は自動では入りません。`![...](images/xx.png)` の行がある位置で、
   note の画像ボタンから対応するファイルを手でアップロードしてください。
   対応表は下にあります。
4. 画像の直後にある一行は、note の画像キャプション欄に移してください。
   本文に残したままでも読めますが、キャプション欄のほうが収まりが良くなります。
5. 記事中の URL は2つとも、行を独立させてあります。note が自動でカード表示に
   変えてくれます。
6. ハッシュタグ欄には `#GIGAスクール` `#小学校` `#算数` `#1年生` `#ICT活用`
   `#Webアプリ` `#計算カード` あたりを想定しています。

装飾については、太字・斜体・表・区切り記号（`→` `／` `：` `▲` `▶`）を
1つも使っていません。見出しだけが Markdown です。

## 画面の撮りかた（撮り直すとき）

```bash
npm i --no-save playwright
npm run build
node <skill>/scripts/serve.mjs . 4180 /Keisan-Card/          # 別ターミナル
node <skill>/scripts/capture.mjs .tmp-shots/shots.mjs \
  --base http://127.0.0.1:4180/Keisan-Card/ --out docs/note/images
```

撮影用のシナリオ `.tmp-shots/shots.mjs` は、納品時に消してあります。
撮り直すときの中身は、この節に書いてあることから組み直せます。

### 撮るときに気をつけたこと

**「まいにち つづける」しくみを本当に撮るために、日付を進めながら実際にれんしゅうを積みました。**
れんぞく記録・がんばりカレンダー・棒グラフは、何日か続けないと中身が出ません。
そこで、ブラウザの時計を 8月3日から8月7日まで1日ずつ進めて、そのつど本当にカードを
最後まで解いています。画面を作りこんだのではなく、5日ぶんの練習が本当にたまった状態です。
11-records-top.png のカレンダーに星が5つ付いているのは、その5日ぶんです。

**書体は本番と同じものを当てて撮りました。** この作業環境からは Google Fonts へ
出られないため、撮影のあいだだけ手もとに書体を中継するしくみを立て、
`index.html` の読みこみ先をそこへ向けました。**撮影後に元へ戻し、
`git status` と `git diff` で差分に残っていないことを確かめてあります。**
書体が届かない環境では端末側の書体になりますが、それは記事にも書いてあるとおりです。

**インストールの案内は Chromebook として撮りました。** 案内の中身は端末の種類で
変わるため、Chromebook を名のる設定で開いています。Chromebook で
「アプリとして インストール」を押し、すぐにインストールできなかったときに出る画面です。

**「きろくを すべて けす」は、確認の画面まで撮って引きかえしました。** 実際には
消していません。撮影後に記録が残っていることを確かめてあります。

## 文体について踏襲したこと

連載の書きぶりに合わせて、次を守っています。

1. 太字・斜体・表・区切り記号を使わない。装飾ではなく文章で強調する
2. 箇条書きは手順のときだけ。導入手順と使いかたのガイド以外は文章で書く
3. 専門用語を日常の言葉に置きかえる。ローカルストレージ、キャッシュ、
   Service Worker といった言葉は本文に一度も出していない
4. 絵文字は見出しだけ
5. 「です・ます」調。子どもは「子どもたち」、読み手は「先生」「先生方」
6. 効果を言い切らない。「〜だと思います」「〜になればいいと思って作りました」まで
7. 機能の説明だけで終わらせず、なぜその作りにしたのかを添える。
   1日あくとリセットにした理由、まちがえたカードを最後にもう一度出す理由、
   「1かいめで せいかい」を足した理由が、それぞれ該当箇所に入っています

本文の字数は約7,800字です。連載の目安である7,000〜9,000字に収まっています。
